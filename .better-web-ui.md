# Design Context

## Users

A single user who wants a lightweight desktop music controller while working. The primary job is to glance at the current track and control playback, progress, volume, and queue without opening a full music app.

## Brand Personality

Calm, focused, and warm. Copy should stay concise and conversational. The interface should feel like a useful desktop companion, not a media dashboard.

## Aesthetic Direction

Dark desktop music island with warm coral for primary playback emphasis and cool periwinkle for secondary controls. Use compact cards, restrained borders, moderate radii, and clear contrast. Avoid dense enterprise dashboards, glossy gradients, and unnecessary chrome. Compact and expanded modes should preserve the same hierarchy.

## Implementation Defaults

Detected project stack takes precedence: Rust 2021 with Slint 1, a `build.rs` UI compilation step, and a single `MainWindow` component in `ui/main.slint`. No web styling system, component library, form stack, table stack, or virtualization library is present. State and playback integration live in Rust; Slint owns presentation and interaction callbacks. This context is inferred from the existing scaffold and README scope.

## Design Principles

1. Make the current track and primary playback action immediately legible.
2. Keep compact mode useful on its own; expansion should reveal detail, not repair missing context.
3. Use warm accent color for playback progress and cool accent color for utility controls.
4. Prefer calm spacing and restrained chrome over dashboard density.
5. Keep the UI state-driven so mock interactions can be replaced by a real playback backend without redesigning the surface.
